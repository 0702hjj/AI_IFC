# breakpoint.md —— 主 agent 断点主持规范

> 交互通道：**opencode `question` 工具弹框**（与 aiplan plan 阶段同款）。

## question 工具（主交互通道）

```
{
  question: "完整问题文本（给用户看的完整问题）",
  header: "简短标签（≤30字）",
  options: [{label: "选项A", description: "说明A"}, {label: "选项B", description: "说明B"}],
  multiple: false,     // 多选（可选）
  custom: true         // 允许用户自定义输入（可选）
}
```

**用法**：
- 缺口追问 / 歧义收敛 / 候选拍板 / 冲突裁决 / **断点确认** → 用 `question` 弹选择框（带 options + custom:true）
- 用户自由表达（一段方案描述）→ 直接在对话里听，让用户自然说话
- 断点回显确认 → 对话里整段复述 + 用 `question` 弹"对吗？A 对 B 改"

## 四步协议（每个断点同构）

1. **收齐断点物**：skeleton.json + geom_check 结论（机器校验报告）
2. **呈现**：对话回显（建筑师语言）+ SVG + 一句话摘要
3. **弹框确认**：`question` 给选项
4. **处置**：确认→封存 / 修改→重派 / 骨架级→回滚

### 断点⓪（S0 预处理）提问示例

```
（对话回显）S0 预处理完成：2 个 zone（塔楼 + 裙房），总面积 1800㎡，
轮廓/核心筒锚点已注入骨架底座——对吗？
（弹框）question({
  question: "S0 预处理完成：2 个 zone（塔楼 + 裙房），总面积 1800㎡，
    轮廓已注入底座——进 S1 骨架设计，对吗？",
  header: "S0 确认（断点⓪）",
  options: [
    {label: "对，进 S1", description: "S0 产物确认，开始骨架设计"},
    {label: "改 plan / 重跑", description: "plan 或预处理有问题，告诉我改哪里"}
  ],
  custom: true
})
```

### 断点①（骨架）提问示例

```
（对话回显）骨架设计完成：塔楼 5 跨×3 跨，核心筒居中偏南，走廊绕核心筒——
南面整排给卧室（朝南采光），北面放楼梯间——对吗？
（弹框）question({

    {label: "对，继续", description: "骨架确认，进房间设计"},
    {label: "要改骨架", description: "告诉我改哪里（改完回断点①重问）"}
  ],
  custom: true
})
```

### 断点②（房间）提问示例

```
（对话回显）F3 标准层：南区分区画了 3 间卧室 + 客厅，东北分区厨房/卫生间
贴核心筒侧，走廊 1.8m——面积都达标，机检通过——对吗？
```

## 交互分层

| 层级 | 内容 | 策略 |
|---|---|---|
| **连问层** | 骨架的多项决策（轴网/核心筒/走廊一次呈现） | **一次 question 弹多个问题**，用户一次答完 |
| **精问层** | 房间的异形/弧面/特殊开间（值得一轮） | **单独精问** |
| **直落层** | 面积区间取端点 / 默认参数 | **类型包默认**，回显带一句，用户无异议即落 |

## 回复分类判据

| 用户回复 | 判据 | 状态转移 | 处置 |
|---|---|---|---|
| **确认** | 无异议（"对，继续"） | → `confirmed`（断点②通过）；建造段 → `sealed` | 解锁 DAG 后继 |
| **局部修改** | 只涉及某层房间/细节 | 声明段 → **`rejected`**（携 feedback，回 `dispatched` 重派）；建造后 → **`build_reject`**（JSON 不动，回 `building` 重派建造） | 改同板块→再问同板块，写 feedback.md 重派该 mission |
| **骨架级意见** | 涉及 core/corridor/轴网/轮廓 | skeleton → `drafting`（回断点①），全部未 sealed mission 作废 | **唯一全局回滚** |

## 修改协议（改同板块→再问同板块）

```
用户: "这层卧室太少，两间改三间"
你  : （更新该层 rooms 草案）
      （对话回显）改好了：这层 3 间卧室，其余房间不变——对吗？
用户: "对"
你  : 该层重新确认 → 建造段
```

**下游复核**（改已确认层时）：
- 改已确认层 N → 查受影响的其他层（共享边/渐退链）→ 回显变更 + 重问
- **换方向**（"改成办公"）→ 回断点① 重走骨架，未确认层按新骨架重推

## 冲突裁决（断点内随时触发）

must 级冲突（如"卧室全朝南" vs "核心筒占南面"），用 `question` 弹裁决框：

```
question({
  question: "卧室全朝南 和 核心筒占南面 打架了——怎么处理？",
  header: "冲突裁决",
  options: [
    {label: "挪核心筒", description: "核心筒移到中间或北面"},
    {label: "部分卧室不朝南", description: "南面留两间，其余朝东/西"},
    {label: "自定义", description: "你来说方案"}
  ],
  custom: true
})
```

## 单断点纪律

- 同一时刻只主持一个确认；其余就绪结果进 **presented 队列**排队（state.json 记录）
- 断点期间：后台就绪的 mission 照跑（用户看图的时间就是并行收益）

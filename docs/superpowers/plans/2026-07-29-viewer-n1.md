## Task 1: Issue schema 扩展 + PgStore + 修改记录（change log）存储与 API

server 侧（`viewer/server/`）：

1. `internal/issue`：`Issue` 增加 `Author string`（json `author`）与 `Provenance`（json `provenance`，结构 `{source: "UI"|"AI"}`）。`Create` 时空值默认 `author="local-user"`、`provenance.source="UI"`；请求显式传入则保留。FileStore 行为同步。
2. `internal/issue` 新增 `PgStore`（pgx/v5 pgxpool）实现同一 `Store` 接口：issues 表 `id text PRIMARY KEY, model_id text NOT NULL, data jsonb NOT NULL, created_at timestamptz NOT NULL`；`SaveScreenshot` 复用文件系统逻辑（截图始终落盘 `models/{id}/issues/`，PgStore 只把相对路径写进 data）。
3. 新包 `internal/change`：`Entry{ID, EntityID, EntityName, Field, OldValue, NewValue, Author, Provenance, CreatedAt}`（json 驼峰）；`Store` 接口 `List(modelID) / Append(modelID, ...*Entry)`；`FileStore`（`models/{id}/changes.json`，tmp+rename 原子写）与 `PgStore`（changes 表，列式 + provenance jsonb）。ID 规则 `c_` + 12 hex（同 issue 的 `i_` 风格）。
4. API：`GET /api/models/{id}/changes` → change 列表（新→旧）。handler 依赖注入 `change.Store`。
5. `cmd/server/main.go`：config 加 `pgDSN` + env `VIEWER_PG_DSN` 覆盖；非空时用 PgStore（issue + change），失败即 fatal；空则 FileStore。
6. 测试：issue schema 默认值单测；change FileStore 单测；API changes 端点 httptest；PgStore 集成测试读 env `VIEWER_TEST_PG_DSN`，未设置则 `t.Skip`（覆盖 issue PgStore CRUD + change PgStore append/list）。
7. `go.mod` 引入 pgx/v5（`go mod tidy`）。

## Task 2: 属性修改器后端（override 阶段）

server 侧：

1. 新包 `internal/override`：白名单字段恰好为 `Name, Description, Classification, FireRating, Comments`（其他字段一律拒绝，40001）。`Store` 接口：`GetAll(modelID) (map[string]map[string]string, error)`（entityID → field → value）、`Set(modelID, entityID string, patch map[string]string) (old map[string]string, err error)`（返回被覆盖前的旧值，无旧值键不存在）。FileStore（`models/{id}/overrides.json` 原子写）+ PgStore（overrides 表 `model_id, entity_id, field, value`，PK 三元组）。
2. API：
   - `GET /api/models/{id}/overrides` → 全量 map（无 override 时 `{}`）
   - `PUT /api/models/{id}/entities/{entityId}/properties`，body `{"fields": {"Name": "X", ...}}`；校验白名单 + 非空 fields + entityId 非空；逐字段写 change log（`oldValue` 取 override 前的生效值，operation 语义 = edit property，provenance `{source:"UI"}`，author `local-user`）；返回该实体当前生效字段 map。空字符串值 = 清除该字段 override（删记录，也写 change log）。
3. main.go  wiring：override store 与 change/issue 同一存储后端（pgDSN 决定）。
4. 测试：白名单校验、old→new change log 写入、清除语义、FileStore 单测、API httptest、PgStore 集成测试（同 skip 规则）。

## Task 3: web 属性编辑 + 修改历史面板

web 侧（`viewer/web/`）：

1. `api/client.ts` + `types.ts`：`fetchOverrides(modelId)`、`saveEntityProperties(modelId, entityId, fields)`、`fetchChanges(modelId)`；沿用既有信封解包与错误处理风格。
2. zustand store：overrides map 进 store（按 modelId 加载）；`applyOverrides(metaObject)` 纯函数：渲染用生效值 = override 覆盖原值（Name 覆盖 metaObject.name；其余按属性条目覆盖/追加到展示数据）。
3. `PropertyPanel`：白名单五字段（Name/Description/Classification/FireRating/Comments）行内可编辑（点击值→input→Enter/失焦保存，Esc 取消）；保存调 `saveEntityProperties`，成功后更新 store overrides；其余字段保持只读。显示生效值，被 override 的字段给出视觉标记（如小圆点/样式）。
4. 底部面板：`IssuePanel` 区域加 tab「Issues / 修改历史」；修改历史列 change log（时间、实体名、字段、old→new、author），新→旧排序，保存属性后刷新。
5. 测试：applyOverrides 纯函数单测、PropertyPanel 编辑交互测试（mock client）、历史 tab 渲染测试。`npm run lint` 与 `npm test` 全绿。

## Task 4: 3D Issue Pin（HTML overlay）

web 侧：

1. 新组件 `IssuePins`（挂在 ViewerPage 画布容器上，absolute 定位层）：对每个有 `entityId` 的 issue，取 `viewer.scene.objects[entityId].aabb` 中心点，`viewer.camera.project` 投影到画布坐标，每帧（xeokit `scene.on("tick")` 或 camera 矩阵变化事件）同步 HTML 钉位置；实体不可见/在屏幕外时钉隐藏。
2. 点击钉 → 选中该 issue（复用 IssuePanel 的视角恢复逻辑：相机 eye/look/up + 面板高亮）。
3. 钉样式：小号圆点 + issue 状态颜色（open/checking/resolved 区分），pointer-events 正确（钉可点、图层其余处穿透）。
4. 测试：投影/可见性判断抽纯函数单测；组件渲染 smoke 测试（mock viewer）。

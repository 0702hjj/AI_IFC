# 01 布局求解器：v2 的心脏

> 输入：分区轮廓多边形 + 气泡图（房间节点×类型×面积区间 + 拓扑边）+ 粗位置提示。
> 输出：每个房间的直角多边形（栅格划分后矢量化）+ 门位候选。
> 要求：确定性（fixed seed 可复跑）、失败可解释（unsat 回喂）、纯轮廓驱动。

## 1. 算法路线调查

### 路线 A：栅格房间分配（raster assignment）——论文主流中间态 ★推荐

**做法**：轮廓按粗网格（如 500mm 或 250mm/格）栅格化为单元集；求解"每个单元
归哪个房间"的分配问题，约束：

- 每个房间的单元集**连通**（4-邻接）
- 单元数 × 单元面积 ∈ 该房间面积区间
- 连通边（door）两侧房间**共享边界**（有公共单元边）
- 包含关系（atrium inside outline）→ 目标房间单元不贴外轮廓
- grid_hints → 房间质心落在指定 5×5 格位（Graph2Plan 同款粗位置）
- 朝向（bedroom faces south）→ 该房间有单元贴南向外轮廓

**论文证据**：RPLAN / Graph2Plan / HouseGAN++ 的生成中间态**全部是栅格掩码**，
再矢量化——栅格→矢量是验证过的管线，我们只是把"神经网络生成掩码"换成
"约束求解生成掩码"。

**求解器选项**：

| 选项 | 依赖 | 确定性 | 失败解释 | 评价 |
|---|---|---|---|---|
| OR-Tools CP-SAT | pip 包（纯 wheel，无系统依赖） | 固定 seed + 固定 worker 数可复现 | unsat / 可行解目标值；可加 slack 变量定位冲突约束 | **首选**，约束是原生表达 |
| 纯 Python 模拟退火 | 零依赖 | fixed seed 可复现 | 无冲突定位，只能报违反清单 | 备选，失控风险低但慢 |
| 贪心 + 局部修复 | 零依赖 | 可复现 | 弱 | 只够 demo |

CP-SAT 建模要点：每单元×每房间一个 Bool；连通性用流约束或限定房间单元数上界
+ 事后检查重试；共享边界用"相邻单元对的颜色不同 ⇒ 构成房间边界"派生。
规模估算：60m×40m 裙房 @500mm = 120×80=9600 单元 × ~6 房间 ≈ 5.8 万 Bool，
CP-SAT 秒级；住宅标准层 24m×18m @250mm ≈ 6912 单元，同级。

**living-room-first 落地**（RPLAN 策略）：不求解器硬编，而是作为**目标函数与
种子**——枢纽房间（连接度最高的节点，住宅=客厅，商场=中庭/走廊）优先给
中心格位 hint 与最大面积初值；求解器一次求解，但目标加权奖励枢纽居中。
若后续要做交互式增量（加一间房重排），再退化为 RPLAN 式逐个放置。

### 路线 B：连续矩形划分（rectangular dual / slicing floorplan）

经典 VLSI 布图理论：平面三角化图 ↔ 矩形对偶（rectangular dual）， slicing tree
递归切割。优点：真矩形房间、无栅格误差；缺点：①非所有图有矩形对偶
（需三角化补边，会引入论文没有的假邻接）;②面积只是区间时自由度大、
解空间跳跃，需要 MIQP（Wu et al. 2018）或元启发（Merrell 2010 贝叶斯+
随机优化、Rodrigues 2013 进化法）;③实现复杂度高一个量级，且失败不可解释。
**结论**：学术上漂亮，工程上不适合作 v2 第一版心脏；留作后补（ solver 输出
粗划分后，可用矩形化精修房间形状）。

### 路线 C：力导向/弹簧系统（Arvin & House 2002）

气泡图当弹簧系统迭代到平衡。快但无可解释失败、无硬约束保证，需另配
合法性检查。仅可作 CP-SAT 失败时的松弛建议器，不作主路线。

## 2. 矢量化（raster → rooms/walls/doors）

求解出栅格分配后（对应 HouseGAN++ 的 segmentation mask → vector 步骤）:

1. 提取每个房间的单元边界 → 直角多边形（像素边界追踪，Moore tracing,
   共线点合并）；凹角保留——真实户型房间本来就是 L 形的。
2. 相邻房间对的公共边界 → 墙段（落在房间分界上）；外边界 → 外墙。
3. 门边（topology via: door）→ 在两房间公共边界上取中点定门位；
   front_door → 该房间贴外轮廓边的中点。
4. 全部坐标 snap 到模数（100mm)，面积回填校验仍在区间内（超界→缩放到
   最近模数解或报 FAIL)。
5. **落盘 layout.json（主线事实源，bim 的机器消费输入）**：房间多边形
   （带类型）、墙段（带两侧房间）、门表（带 via 类型）、预锁标记，
   过 `layout_output.schema.json`。
6. DXF 渲染支线：archdxf 消费 layout.json 出图——外墙/隔墙/开洞/门 swing
   全部走 v1 画法库，图层/标注/校验器不变。**DXF 是工程产物（人看）,
   不是求解层的产出目标；求解层的产出目标只有 layout.json。**

**栅格误差控制**：单元 250-500mm + snap 100mm，面积区间本来就给了
±10% 级容差（RPLAN 面积区间证据）;cad 校验器最后兜底。

## 3. 失败回喂（C 防线的 v2 形态）

| 失败类型 | 检测 | 回喂给模型的信息 |
|---|---|---|
| 面积区间与轮廓总面积矛盾 | 求解前算术预检 | "面积需求合计 820-950㎡,轮廓可用 760㎡,超 8-25%" |
| 拓扑不可满足（如 A 邻 B 且 A 不贴边但轮廓只能让 A 贴边） | CP-SAT unsat + 逐约束 slack 重跑 | 冲突约束清单 + 建议松哪条 |
| 门边两侧无公共边界 | 矢量化阶段 | "shop-corridor 有 door 边但求解结果不相邻" |
| 求解超时 | 时限 | 建议放宽区间/减少 hint |

模型收到回喂后改气泡图（plan.json draft）重跑——**FAIL 循环从几何层上移
到关系层**，这正是 v2 的颠覆点。

## 4. 选型结论（待用户拍板）

1. 主路线：**A 栅格分配 + CP-SAT**(OR-Tools 单一 pip 依赖，确定性可控）。
2. 矢量化：单元边界追踪 + 100mm 模数 snap + archdxf 复用。
3. living-room-first 作为目标权重与 hint 种子，不做硬管线。
4. 路线 B（矩形对偶精修）列后补；路线 C 不采用。
5. 求解器归属：`skills/aidxfv2/scripts/packages/layout/`（与 archdxf 平级的新包）。

## 5. 待定项

1. OR-Tools 依赖可接受？（纯 wheel；若坚持零依赖 → 退纯 Python SA，性能与
   可解释性打折）
2. 网格粒度：500mm 起步？住宅 250mm？还是统一 250mm?
3. 房间形状是否允许 L 形（单元并集自然产生），还是限定矩形（加约束，
   可能降低可满足性）?——倾向允许 L 形，贴合真实户型。
4. 多楼层 stair/elevator 核心筒：作为**固定障碍单元**预先锁定（从
   vertical_relations 派生），还是作为普通房间参与求解？——倾向预锁定。
